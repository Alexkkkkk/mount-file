# MountFile / issue #182 — audit-level review

**Дата:** 2026-10-29  
**Проверенный commit:** `b500869d6404d8f11058b9e267e48f10aeca9b58`  
**Ветка:** `work/issue-182`  
**Объект:** native VFS, bounded readers, native writers, routing, extraction, rollback, benchmarks и документационный контракт.

## Вердикт

Архитектура проекта находится в хорошем состоянии для консервативного native read-only перехода: native backend выбирается внутри процесса, границы image/partition передаются явно, unknown/dirty/recovery profiles по умолчанию отклоняются, а `pytsk3` доступен только как явно включаемый compatibility fallback.

Issue #182 как стратегический roadmap **ещё не закрыт полностью**. Готовы native read-only и ограниченные write-профили. Не готовы journal-aware writers для ext3/ext4, NTFS transactional write path, полноценный recovery/replay, полная ext4 checksum/64-bit parity, FUSE/WinFsp/macFUSE adapter и полная cross-platform failure-injection matrix.

Этот отчёт разделяет фактически проверенное, частично готовое и не заявляемое. `1187 passed` не трактуется как доказательство проверки Windows/macOS или всех optional differential tools.

## 1. Что готово

### Native routing и VFS

- `mountfile/vfs.py` остаётся единой точкой VFS; параллельный VFS не создан.
- Native routing работает offline по умолчанию.
- Для неизвестных форматов `pytsk3` не запускается автоматически.
- Legacy fallback разрешается только через `MOUNTFILE_ALLOW_LEGACY_TSK=1` или `allow_legacy_fallback=True`.
- Распознанный, но dirty, malformed или unsupported профиль не понижается до скрытого fallback.
- Providers публикуют `backend_name`, `read_capabilities`, `write_capabilities` и `backend_status`.

Ключевые места: `mountfile/vfs.py`, `mountfile/vfs_api.py`, `mountfile/universal_fs_rw.py`, `tests/test_issue_182_acceptance.py`, `tests/test_vfs_api.py`.

### Read profiles

| Профиль | Статус | Ограничения |
|---|---|---|
| FAT12/16/32 | готов bounded read-only | native tree/read; writer capability зависит от выбранного FAT profile |
| ext2 | готов bounded read-only | clean revision 0/1, 1/2/4 KiB, allowlist features |
| ext3 | частично готов read-only | classic layout + ограниченная JBD2 validation; replay только explicit in-memory overlay |
| ext4 | частично готов read-only | ограниченный classic/extent profile; checksum/64-bit/flex/meta layouts fail-closed |
| NTFS | частично готов bounded read-only | boot/MFT/USA/attributes/runlists/indexes/$Volume/$LogFile checks; no replay, no writes |
| exFAT | готов ограниченный bounded read-only | single FAT, validated boot/bitmap/upcase metadata and bounded chains |

Read API: `list`, `stat`, `read-range`, `extract`. Native extraction использует bounded chunks и atomic temporary-file replacement.

### Native writes

- ext2 phase-one writer: clean, non-journaled, allowlisted profile;
- exFAT writer: ограниченный explicitly routed profile;
- FAT writer: существующий bounded profile с staging/hash/rollback guards;
- ext3/ext4/NTFS native writes: **не включены**.

Для ext2 writer поддерживается только `12 + block_size / 4` data blocks через direct + single-indirect addressing. Максимальные размеры одного файла примерно такие:

| Block size | Максимум data blocks | Приблизительный максимум |
|---:|---:|---:|
| 1 KiB | 268 | 268 KiB |
| 2 KiB | 524 | 1.02 MiB |
| 4 KiB | 1036 | 4.05 MiB |

Превышение лимита отклоняется до начала мутации. Double/triple-indirect, sparse files, indexed directories и unsupported inode flags не «чинятся» автоматически.

Native ext2 writer и FAT/exFAT staging имеют rollback/quarantine paths, но не являются универсальной power-loss atomicity гарантией. Read-back проверяет логическую корректность и не доказывает отсутствие torn writes на storage hardware.

## 2. Модель угроз

| Угроза | Реальный вектор | Текущий контроль | Остаточный риск |
|---|---|---|---|
| TOCTOU | image меняется между hash и commit | source hash, same-file checks, writer guards | best-effort; OS/storage lock semantics не унифицированы между POSIX/Windows |
| Tampering | malformed image выходит за selected extent | bounded reads, explicit `offset/volume_size`, checked geometry | нужен единый публичный `checked_range` contract для всех backend-ов |
| Information disclosure | unwritten/sparse storage содержит stale bytes | ext4 unwritten -> zero; NTFS sparse rejected; unsupported streams rejected | differential coverage на реальных images ещё ограничено |
| DoS | cluster/runlist/depth fields провоцируют большие аллокации или циклы | chain limits, directory/read limits, visited sets, depth/entry caps | нет полной property/fuzz campaign и subprocess sandbox |
| Repudiation | пользователь не знает точную причину отказа | human-readable errors и backend status | typed refusal codes ещё не централизованы |
| Elevation/RCE | in-process parser обрабатывает untrusted bytes | fail-closed parsing и bounded allocations | процесс не изолирован sandbox-ом |

## 3. Byte-level review

### ext2/ext3/ext4

Положительные проверки:

- ext2 read path покрывает direct, single-, double- и triple-indirect mappings;
- ext2 writer не принимает double/triple-indirect profile;
- ext4 extent tree проверяет magic, depth, sorted keys, bounds, cycles и unwritten extents;
- unwritten extents возвращаются как логические нули;
- `metadata_csum`, `64bit`, `flex_bg`, `meta_bg`, inline data, htree и unsupported ext4 features остаются fail-closed;
- dirty/recovery-required state отклоняется до routing.

Ограничение: это не полная ext4 parity. Включение новых feature bits допустимо только вместе с checksum/layout validators, regression fixtures и independent differential checks.

### NTFS

Положительные проверки:

- boot-sector geometry и selected volume bounds;
- MFT/MFTMirr и FILE-record USA/fixups;
- resident/nonresident attributes и bounded runlists;
- sequence/parent references и directory index structures;
- `$Volume` state;
- обе restart pages `$LogFile` и clean-state consistency.

Fail-closed ограничения:

- `ATTRIBUTE_LIST` streams;
- sparse/compressed/encrypted streams;
- journal replay;
- native writes.

Следовательно, reader не должен выдавать частичный `$DATA` как полный файл. Unsupported attribute list — явный отказ.

### exFAT

Положительные проверки:

- boot region, geometry и volume bounds;
- single-FAT policy;
- cluster-chain cycles and capacity;
- bounded directory size;
- entry-set checksum, name hash, UTF-16 names;
- allocation bitmap/upcase metadata;
- provider-specific maximum read range.

`VolumeFlags != 0` и unsupported multi-FAT profiles отклоняются намеренно. Это нужно считать частью публичного profile contract, а не общей ошибкой «unsupported filesystem».

### FAT

FAT read/write code имеет существующие проверки границ, chains, LFN/catalog behavior и rollback scenarios. Отдельно остаётся документировать FSInfo `Free_Count` policy для каждого writer profile: обновление или `0xFFFFFFFF` (`unknown`).

## 4. Crash consistency и FMEA

### Высокий риск

| ID | Failure mode | Severity | Почему read-back недостаточен | Текущий контроль |
|---|---|---:|---|---|
| W1 | torn write при power loss | 9 | page cache read-back не доказывает физическую запись | staging/rollback; power-loss atomicity не заявляется |
| W2 | metadata/data ordering | 9 | корректность видна только до сбоя | native ext3/ext4/NTFS writes отключены |
| W3 | rollback failure | 9 | образ может остаться промежуточным | quarantine + retained rollback snapshot |
| W4 | concurrent modification | 8 | hash window и same-region writes могут пересекаться | source hash/recheck; best-effort contract |
| W5 | allocation metadata mismatch | 8 | counters могут выглядеть согласованно частично | independent checks и fixtures; полная matrix не закрыта |

Честный контракт текущего профиля:

> ext2 и ограниченный exFAT/FAT writer не являются универсально crash-safe при внезапном отключении питания. Rollback, staging и read-back снижают программный риск, но не заменяют on-volume journaling, hardware barriers или атомарную замену всего image.

Для ext3/ext4/NTFS native write до сих пор требуется journal-aware ordering/recovery path. Host snapshot не считается заменой filesystem journal.

## 5. Capability matrix

### Read

```text
FAT12/16/32  -> list, stat, read-range, extract
ext2         -> list, stat, read-range, extract
ext3/ext4    -> list, stat, read-range, extract (accepted bounded profiles only)
NTFS         -> list, stat, read-range, extract (accepted metadata/tree profiles only)
exFAT        -> list, stat, read-range, extract (accepted bounded profiles only)
```

### Write

```text
ext2         -> put/replace, mkdir, same-directory rename, delete; phase-one limits
FAT          -> only explicitly selected bounded native profiles
exFAT        -> only explicitly selected limited profile
ext3/ext4    -> none
NTFS         -> none
```

Any unsupported operation must return an explicit rejection. Browsability never implies mutability.

## 8. Ready / not ready matrix

### Ready now

- offline native routing by default;
- explicit legacy fallback opt-in;
- bounded FAT and ext2 read profiles;
- bounded ext3/ext4/NTFS/exFAT read-only profiles where documented;
- ext2 phase-one writer;
- limited exFAT/FAT writer paths;
- explicit capability reporting;
- bounded extraction;
- rollback/quarantine paths and failure tests for implemented writers;
- reproducible benchmark harness;
- installer dry-run regression fixed in `b500869`.

### Not ready / must not be claimed as complete

- native ext3 writer;
- native ext4 writer;
- native NTFS writer;
- full JBD2 recovery/replay including wraparound, revoke, checksums and checkpointing;
- full ext4 metadata checksum/64-bit/flex/meta/inline parity;
- NTFS `$LogFile`-aware transactions and `ATTRIBUTE_LIST` write support;
- FUSE/WinFsp/macFUSE OS mount adapter;
- complete Windows/macOS execution matrix;
- complete property-based/fuzz corpus and kill/crash matrix;
- final benchmark acceptance against a pinned pytsk3/libtsk baseline.

## Final status for issue #182

**Status: substantially implemented, not fully closed.**
